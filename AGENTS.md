# Project instructions

Read [docs/AGENTS.md](docs/AGENTS.md) and the relevant core documents before substantial work. That file centralizes this project's agent instructions; keep this root file as a discovery pointer.

Per the current rule in `docs/AGENTS.md`, each task must use skills: read the local vendored `SKILL.md` linked in `plans.md`/`docs/AGENTS.md` for the 2-4 relevant skills before doing the work, and report which skills were used in that part's summary. Project documents override generic skill advice.

Part 7 adds the Ollama embedding adapter with the Nomic prefixes, bounded retry, and vector validation under apps/api; it is approved and published on origin/main. Embedding sends `truncate: false` so over-long input errors instead of being silently trimmed, validates exactly 768 finite values, re-reads the model digest before every embedding and fails closed when it differs from the required `OLLAMA_EMBED_DIGEST`, and bounds each attempt with a real wall-clock deadline. Part 8 then adds the durable ingestion worker under apps/api/app/ingestion with the manager upload routes in apps/api/app/api/manager.py: a `.md`/`.txt` upload is validated before any write, staged as a pending job with a server-generated document id and revision, claimed with FOR UPDATE SKIP LOCKED under a 120-second lease renewed every 30 seconds, and every staging write and activation is fenced on a per-claim token and on the lease expiry, so an expired lease is refused even when nobody reclaimed the job; the expiry is compared against the database's live clock rather than now(), because now() is the transaction start time and goes stale while a transaction waits on a lock; a statement's qualification is also evaluated before its wait, so the check is repeated after the lock is held, and activation repeats it once more after its last lock (advisory, then job row, then document row) and immediately before any mutation, so no wait that outlives the lease can slip through. Activation is one transaction that compare-and-swaps the expected current revision and atomically reserves the chunk quota under the publisher lock, so a failed job leaves the previously published revision searchable and two concurrent publishers cannot both take the last room. The upload route parses no body until Origin and the manager role have been checked, and an ASGI guard caps the whole multipart body while streaming. Part 8 is approved and published on origin/main.

Part 9 added the operator corpus import (`uv run --locked python -m app.cli.import_corpus`), which validates all 20 fixed corpus files before any write, preserves their document ids and takes each role from an operator allowlist; it is idempotent and rejects an existing id whose text or policy differs. It also completed the manager page at `/manager/documents` with the list, upload, job status and safe Persian error messages, polling every 5 seconds. Part 9 is approved and published on origin/main.

Part 10 (document replacement and logical delete) is approved and published on origin/main. Migration `0002` adds two nullable columns, `documents.staged_access_role` and `documents.staged_title`, and its constraint names are wrapped in `op.f()` in both directions so the `ck_` naming convention is applied exactly once; without that the upgrade doubled the prefix and the downgrade could never drop the constraint. A document's effective `access_role` and `title` never hold a not-yet-activated value: narrowing access is applied immediately when the replacement is staged and is deliberately *not* rolled back if the replacement fails, while widening and the title are applied only at activation, in the same transaction that publishes the text. `app/ingestion/sections.py` keeps section identifiers stable across a replacement — preserved sections are matched by title and a new section takes an identifier above the highest one that document has ever used, never a recycled gap, because the section id is the citation handle. `store.stage_replace` refuses a second non-terminal job for one document with 409, which covers the create job too, since a document that has published nothing has no revision to replace. `store.soft_delete_document` is logical and idempotent: it keeps `current_revision` and the published rows, fails every open job and clears its lease so an in-flight worker stops at its next fenced write, clears the staging columns, and removes revisions that were never published — taking locks in publisher advisory → document row → job rows order, matching `activate_revision`'s lock order. Activation additionally refuses an inactive document. The web proxy allows `PUT`/`DELETE` on one document with an allowlisted id shape, requires the web Origin on every write, and answers `204` without inventing a body; `UploadGuard` now covers `PUT` as well as `POST`, so an oversized replacement is refused before it is buffered.

Part 11 (authorized hybrid retrieval) is implemented and validated but **approved and published on origin/main**. The `apps/api/app/retrieval/` package builds the allowlist as a **SQL predicate**, not a post-filter: one statement carries `status = 'active'`, `current_revision IS NOT NULL`, an `EXISTS` for a `ready` job on that revision, and the permitted `access_role`, and both search paths are built from it. Filtering after ranking would leave the database ranking rows the actor may not read, which makes the hit count depend on forbidden documents and leaves safety resting on nobody forgetting the filter. BM25 matches on **token overlap, never on the score's sign**: `rank_bm25` floors a negative IDF at a fraction of the corpus's average IDF, and on a small corpus where a term appears in every document that average is negative too, so a perfectly matching chunk scores negative and a `score > 0` test returns nothing at all. Two further properties the review pinned down: the fused candidates are re-read under the allowlist **immediately before returning**, because two reads in one snapshot do not stop an access narrowing that lands between them, and `store.assert_index_consistent` compares the stored provider/model/digest/dimension against the live provider **before anything is ranked** - scoped to the eligible domain rather than the whole table, so one actor's availability never depends on rows they may not read. The question is normalized once and that one string goes to both paths, and a provider failure exits with a fixed message and a non-zero code rather than a traceback, because the adapter's message can quote back the question. Retrieval never writes, has no fallback path, and exposes no text: `app/cli/retrieval_report.py` prints identifiers, ranks, the fused score and the role it applied, never chunk text, section source, document title or the question itself.
