# Enterprise Knowledge Copilot — راهنمای اجرا

دستیار پرسش‌وپاسخ روی اسناد منابع انسانی و عملیات شرکت فرضی «سپهر داده»، برای نمونه‌کار مسیر AI Engineer.

**وضعیت:** پارت ۱۹ در 2026-10-12 با SHA `cfa1a5e3005f2f4441cdbebe3428792d4adb7cb9` روی `origin/main` منتشر شد. شواهد و تاریخ هر بررسی در [راهبرد آزمون](docs/TESTING.md) آمده‌اند؛ فرمان‌های راه‌اندازی در این فایل دستور اجرا هستند و به معنی اجرای دوبارهٔ همهٔ آن‌ها در این نوبت نیستند. ترتیب، وضعیت و تاریخچهٔ هر پارت در [برنامهٔ اجرا](docs/plans/plans.md) است.

هشت پارت نخست یک scaffold محلی، رابط فارسی RTL، پایگاه‌داده، احراز هویت، نماهنگی متن و بارگذاری index ساختند. پارت‌های ۹ تا ۱۸ جست‌وجوی ترکیبی مجاز، جایگزینی و حذف سند، گزارش‌های عملیاتی، پاسخ مستند با نقل‌قول اعتبارسنجی‌شده، صفحهٔ نمایش منبع، مسیر انتها‌به‌انتها و ارزیابی تکرارپذیر را اضافه کردند. پارت ۱۹ راهنمای اجرای محلی را تکمیل و لاگ ساختاریافتهٔ محدود به فیلدهای مجاز را اضافه کرد.

همهٔ اسناد، سیاست‌ها و افراد ساختگی‌اند و برای مشاورهٔ حقوقی یا استفاده در شرکت واقعی تهیه نشده‌اند.

## راه‌اندازی از صفر

پیش‌نیازها: Python 3.12 با [`uv`](https://docs.astral.sh/uv/)، Node.js 22 یا بالاتر با npm، و PostgreSQL 16 با `pgvector`. وضعیت این پروژه با Python 3.12.3، uv 0.12.18، Node 24.13.0 و npm 11.6.2 سنجیده شده است.

### ۱. تنظیمات

```bash
cp .env.example .env
chmod 600 .env
```

> **هر بلوک کد در این راهنما از ریشهٔ مخزن شروع می‌شود.** بلوک‌هایی که به `apps/api` یا `apps/web` می‌روند داخل یک **subshell** نوشته شده‌اند — یعنی `(cd … && …)` — تا ترمینال شما سر جایش بماند و بلوک بعدی از مسیر غلط شروع نشود. اگر بلوک‌ها را بدون پرانتز و پشت‌سرهم در یک ترمینال اجرا کنید، `cd` دوم به `apps/api/apps/api` می‌رسد که وجود ندارد.
>
> استثنا فقط سرویس‌های ماندگار است که هرکدام بلوک و ترمینال خودشان را دارند و با `# ترمینال` علامت خورده‌اند؛ آنها برنمی‌گردند، پس ترمینالشان هم در همان پوشه می‌ماند.

حداقل این کلیدها را در `.env` پر کنید:

| کلید | چه چیزی است |
|---|---|
| `OPENROUTER_API_KEY` | تولید پاسخ. بدون آن `/ask` پاسخ نمی‌دهد. |
| `DB_PASSWORD` | رمز کاربر محدود پایگاه‌دادهٔ پروژه. |
| `SEED_EMPLOYEE_PASSWORD` | رمز حساب کارمند. دست‌کم ۱۲ نویسه. |
| `SEED_MANAGER_PASSWORD` | رمز حساب مدیر. دست‌کم ۱۲ نویسه. |
| `OLLAMA_EMBED_DIGEST` | digest مدل embedding. `preflight_embedding` مقدار درست را چاپ می‌کند. |

`WEB_ORIGIN` را همان‌گونه که هست نگه دارید. این کنترل Origin است و `http://localhost:3000` با `http://127.0.0.1:3000` **دو مبدأ متفاوت‌اند**: اگر صفحه را با یکی باز کنید و درخواست‌ها با دیگری بروند، ورود با ۴۰۳ رد می‌شود و پیامش هیچ شباهتی به خطای مبدأ ندارد.

### ۲. پایگاه‌داده

آماده‌سازی **یک‌باره** و فقط با **superuser موجود سرویس** (`rag`). حساب کاربرد `enterprise_knowledge_copilot` که در `.env` می‌گذارید superuser نیست و `CREATEDB`/`CREATEROLE` ندارد، پس با آن نمی‌توان این اسکریپت را اجرا کرد. روش زیر عیناً همان است که header خود `provision.sql` و [DATABASE.md](docs/DATABASE.md) می‌نویسند:

```bash
# مقدار DB_PASSWORD را از .env در همین shell وارد کنید؛ cp کردن فایل آن را export نمی‌کند.
# این شکل آن را در تاریخچهٔ shell هم نمی‌نویسد:
read -rs DB_PASSWORD && export DB_PASSWORD && echo

(
  cd apps/api
  umask 077
  env_file="$(mktemp)"
  trap 'rm -f "$env_file"' EXIT
  printf 'EKC_DB_PASSWORD=%s\n' "$DB_PASSWORD" > "$env_file"
  docker exec -i --env-file "$env_file" rag-postgres \
    psql -q -U rag -d postgres -v ON_ERROR_STOP=1 -f - < sql/provision.sql

  uv run --locked alembic upgrade head
)
```

رمز از راه `EKC_DB_PASSWORD` **داخل کانتینر** به `psql` می‌رسد، نه در URI و نه در آرگومان فرایند. اگر رمز را داخل connection string بگذارید، در `argv` پروسهٔ `psql` دیده می‌شود و برای هر کسی که `ps` را بتواند بخواند قابل استخراج است — و این خلاف قرارداد صریح اسکریپت است.

برای بررسی بدون هیچ تغییری، `-v dry_run=1` به فرمان `psql` اضافه کنید. اسکریپت idempotent است: هر دو پایگاه `enterprise_knowledge_copilot` و `enterprise_knowledge_copilot_test` را می‌سازد و اجرای دوباره بدون تغییر می‌ماند.

### ۳. حساب‌ها و corpus

```bash
(
  cd apps/api
  DB_NAME=enterprise_knowledge_copilot uv run --locked python -m app.cli.seed_accounts
  uv run --locked python -m app.cli.import_corpus --manager-login manager
  uv run --locked python -m app.cli.run_worker --max-jobs 20
)
```

`seed_accounts` رمزها را از متغیرهای محیط می‌خواند و هرگز آن‌ها را تغییر نمی‌دهد یا چاپ نمی‌کند؛ اگر رمز کوتاه باشد متوقف می‌شود. `import_corpus` فقط بیست سند ثابت مخزن را می‌پذیرد و اجرای دوباره‌اش بی‌اثر است.

`run_worker --max-jobs 20` اینجا یک **bootstrap یک‌باره** برای همان corpus اولیه است و پس از خالی‌شدن صف تمام می‌شود. برای ادامهٔ کار — هر بار که سندی از رابط بارگذاری یا جایگزین می‌کنید — worker **مقیم** بخش ۵ را بالا نگه دارید.

پس از پایان، کارمند ۱۶ سند و مدیر ۲۰ سند با ۸۰ قطعه می‌بینند.

### ۴. بررسی اتصال‌ها

```bash
(
  cd apps/api
  uv run --locked python -m app.cli.preflight_embedding
  uv run --locked python -m app.cli.preflight_generation
)
```

اگر `preflight_embedding` شکست بخورد، index ناقص ساخته شده و بازیابی بعداً نتیجهٔ غلط می‌دهد؛ به همین دلیل در برابر digest زنده بسته می‌شود. `preflight_generation` ساختار پاسخ و مصرف واقعی را نشان می‌دهد و هیچ متنی از اسناد شما را چاپ نمی‌کند.

### ۵. اجرای سرویس‌ها

**سه ترمینال جدا، هرکدام از ریشهٔ مخزن.** سرویس سوم را نیاز دارید: `API` سند را stage می‌کند و هیچ‌چیز را پردازش نمی‌کند؛ تنها worker است که آن را قطعه‌بندی و برداری می‌کند.

هر کدام در **ترمینال خودش**، که از ریشهٔ مخزن شروع می‌شود. اینها سرویس‌های ماندگارند و برنمی‌گردند، پس هرکدام ترمینال جدا می‌خواهند. سه بلوک جدا هستند نه یکی، تا معلوم باشد کدام با کدام اجرا می‌شود:

```bash
# ترمینال ۱ — API
cd apps/api && uv run --locked python -m app
```

```bash
# ترمینال ۲ — رابط
cd apps/web && npm ci && npm run build && npm start   # http://localhost:3000
```

```bash
# ترمینال ۳ — worker مقیم ingestion (بدون --max-jobs)
cd apps/api && uv run --locked python -m app.cli.run_worker
```

`npm run dev` هم کار می‌کند، ولی `npm run build && npm start` همان چیزی است که در production محلی اجرا می‌شود و در بخش بررسی همین آزموده شده است.

اگر worker مقیم را بالا نیاورید و بعد از راه‌اندازی اولیه سندی بارگذاری یا نسخه‌ای جایگزین کنید، آن job در صف می‌ماند و صفحهٔ `/manager/documents` آن را `pending` نشان می‌دهد تا ابد — چون API تنها job را stage می‌کند.

اجرای `--max-jobs N` در بخش ۳ یک bootstrap یک‌باره است: پس از N کار یا خالی‌شدن صف **تمام می‌شود** و برای بارگذاری‌های بعدی دوباره لازم است.

## سناریوی نمایشی

سرور را با دست بالا باز کنید و با حساب `employee` وارد شوید.

۱. **`/login`** — ورود. یک درخواست از مبدأی دیگر ۴۰۳ می‌گیرد و هیچ کوکی نشستی صادر نمی‌شود.
۲. **`/ask`** — بپرسید: «سهم مرخصی سالانهٔ کارمند چند روز کاری است؟»
۳. پاسخ با یک یا چند ادعا و **استناد** می‌آید. هر ادعا یک نقل‌قول دارد که پیش از ارسال در متن همان بخش از سند معتبر شده است.
   **اگر حتی یکی از ادعاها معتبر نباشد، کل پاسخ رد می‌شود** و یک خطای عمومی می‌بینید. ادعاها یکی‌یکی سرو نمی‌شوند و هیچ ادعای نامعتبری «حذف» نمی‌شود تا بقیه باقی بمانند.
۴. دو چیز را از هم جدا نگه دارید. **امتناع** یعنی مدل گفت شواهد کافی نیست و سامانه آگاهانه از پاسخ دادن دست کشید — این یک پاسخ درست است. **خطای اعتبارسنجی** یعنی مدل چیزی را نقل کرد که در passage مجاز نبود، یا به منبعی ارجاع داد که هرگز نگرفته بود — این یک شکست است، نه یک پاسخ. یکی دانستن این دو یعنی کاربر برای خطایی retry می‌کند که نتیجه‌اش باز هم همان خطاست.
۵. آنچه اعتبارسنجی **اثبات** می‌کند این است که نقل‌قول واقعاً در متن همان passage هست؛ یعنی ادعا روی سندی تکیه دارد که سند واقعاً آن را می‌گوید. آنچه اثبات **نمی‌کند** این است که جملهٔ ادعا لزوماً از آن نقل‌قول نتیجه می‌شود: جملهٔ ساختگی با نقل‌قول واقعی می‌تواند از بررسی مکانیکی بگذرد. **درستی معنایی کار بازبینی انسانی است.**
۶. روی استناد کلیک کنید. صفحهٔ **`/sources`** همان بخش و همان نسخه را نشان می‌دهد. آدرسی که مرورگر باز می‌کند
   `/sources?document=…&section=…&revision=…` است — سه پارامیر در query.
   این با آدرس JSON که خود صفحه پشت‌صحنه می‌خواند یکی نیست:
   `/api/sources/{document_id}/sections/{section_id}?revision=…` — یک مسیر و **فقط یک** پارامیر.
   دو آدرس جدا هستند چون یکی صفحه‌ای است که آدم باز می‌کند و دیگری خواندن JSON پشت نشست؛ اگر یکی را جای دیگری به‌کار ببرید، بازرس متن صفحه را به‌جای متن سند می‌گیرد.
۷. **با حساب `manager` وارد شوید** و بپرسید: «بودجهٔ برنامه‌ریزی آموزش هر تیم در هر دورهٔ ۱۲ماهه چقدر است؟» پاسخ به سند `MGR-003` استناد می‌کند.
۸. **با حساب کارمند همان دستهٔ استناد را باز کنید.** ۴۰۴ می‌گیرید، بدون متن سند و بدون اینکه پاسخ وجود سند را تأیید کند. این یک آزمون مجوز واقعی است: همان سند، همان بخش، همان نسخه — چند لحظه پیش برای مدیر خوانده شد.
۹. **`/manager/documents`** (فقط مدیر) — فهرست اسناد، بارگذاری `.md`/`.txt` تا ۱ MiB، جایگزینی نسخه و حذف منطقی. وضعیت هر کار پردازش هر ۵ ثانیه به‌روز می‌شود. **اینجا worker مقیم بخش ۵ لازم است**، وگرنه وضعیت روی `pending` می‌ماند.

مرز نقش در API و در proxy رابط هر دو اعمال می‌شود؛ رابط یک allowlist مسیر است و API مرجع نهایی احراز هویت و مجوز.

## گزارش‌های عملیاتی

چهار فرمان که بدون رابط کارگری می‌گویند سامانه چه می‌کند. هر چهار نقش را از رکورد کاربر در پایگاه‌داده می‌خوانند، نه از یک پرچم خط فرمان.

| فرمان | چه چاپ می‌کند | چه **نمی‌چاپند** |
|---|---|---|
| `retrieval_report` | رتبه، امتیاز ادغام‌شده، نقش اعمال‌شده، شناسهٔ سند/بخش/نسخه | متن قطعه، عنوان سند، متن سؤال |
| `answer_report` | تعداد ادعای معتبر، شناسهٔ منابع، abstain، اجزای ناقص، مصرف | متن پاسخ و نقل‌قول |
| `generation_report` | provider، مدل، تعداد شواهد ارسالی، شناسهٔ استناد، مصرف | خودِ متن مدل |
| `eval_run` / `eval_score` | Recall، MRR، نشت، رفتار، latency، provenance | متن سند و متن پاسخ |

```bash
(
  cd apps/api
  uv run --locked python -m app.cli.retrieval_report \
    --login manager --question 'سقف هزینهٔ آموزشی فردی چقدر است؟'
  uv run --locked python -m app.cli.answer_report \
    --login manager --question 'سقف هزینهٔ آموزشی فردی چقدر است؟'
  uv run --locked python -m app.cli.generation_report \
    --login employee --question 'سهم مرخصی سالانهٔ کارمند چند روز کاری است؟'
)
```

خروجی واقعی `retrieval_report` روی همین پروژه:

```
config: lexical_top_k=20 vector_top_k=20 rrf_k=60 final_top_k=5
rerank: disabled (no provider call was made)
hits: 5
  1. MGR-003#MGR-003-S1@d51ee8fa… role=manager lexical=1 vector=1 fused=0.032787 rerank=None
  2. HR-005#HR-005-S1@2c61e181…     role=employee lexical=2 vector=3 fused=0.032002 rerank=None
```

دو نکته که در طراحی این گزارش‌ها دیده می‌شوند:

- **`generation_report` پاسخ را تأیید نمی‌کند.** آنچه مدل ادعا کرده یک assertion تأییدنشده است؛ اعتبارسنجی نقل‌قول و دروازهٔ نهایی کار `answer_report` و `/ask` است. این تفاوت عمدی است تا کسی ادعای مدل را پاسخ حساب نکند.
- **`retrieval_report` پرچم `--show-text` ندارد** و هرگز متن چاپ نمی‌کند. این تنها راه دیدن اینکه بازیابی چه می‌کند بدون رابط کارگری است.

## ارزیابی

معیار ثابت چهل‌نمونه‌ای در `eval/questions.jsonl` است (digest `sha256:a8fb0b724663…`).

```bash
# اجرای تازه: به DB و provider وصل می‌شود، سهمیه مصرف می‌کند و artifact را می‌نویسد.
(
  cd apps/api
  uv run --locked python -m app.cli.eval_run --out ../../eval/runs/run.json
)
```

```bash
# بازمحاسبه: فقط artifact را می‌خواند. نه DB، نه provider، نه هزینه‌ای.
(
  cd apps/api
  uv run --locked python -m app.cli.eval_score ../../eval/runs/run.json
)
```

این دو را با هم قاطی نکنید. `eval_score` تنها فرمانی است که می‌توانید روی artifact **موجود** اجرا کنید بی‌آنکه چیزی را بازنویسی کند؛ اگر پیش از آن دوباره `eval_run` را اجرا کنید، یک اجرای تازه ساخته‌اید نه بازمحاسبهٔ اجرای قبلی، و فایل قبلی روی همان مسیر نوشته شده است.

`eval_score` ارقام artifact را از روی ردیف‌های خودش دوباره حساب می‌کند و می‌گوید آیا با هم می‌خوانند. اگر نخوانند، `eval_run` اعداد را از خودش نوشته و گزارش داده است. `configuration` و `usage` عمداً بازمحاسبه نمی‌شوند، چون از خود artifact به‌تنهایی بازسازی‌پذیر نیستند.

### آنچه واقعاً سنجیده شده و آنچه نشده

آخرین اجرای کامل ۴۰ نمونه‌ای روی این corpus:

| سنجه | مقدار |
|---|---|
| Recall@۵ کل | ۰٫۸۵۸ |
| — به تفکیک دسته | direct ۱٫۰۰۰ · multi_document ۰٫۷۱۷ · access_security ۰٫۶۶۷ |
| — به تفکیک نقش | employee ۰٫۸۷۷ · manager ۰٫۷۵۰ |
| نشت | ۰ از ۷ نمونهٔ محرمانه |
| رفتار | ۴۰ بررسی: ۱۳ امتناع، ۲۷ پاسخ |
| provenance | `unchanged` — کد و corpus در طول اجرا تغییری نکردند |

**این ارقام با بازیابی واقعی و تولید استاب‌شده به‌دست آمده‌اند، نه با پاسخ واقعی مدل.** دلیلش سهمیهٔ روزانهٔ tier رایگان است. آنچه **سنجیده نشده** و نباید از این اعداد برداشت شود:

- **درستی معنایی پاسخ.** پوشش `required_facts` و اینکه جملهٔ ادعا واقعاً از متن نتیجه می‌شود، بازبینی انسانی است و در [راهنمای ارزیابی](docs/evaluation-guide.md) تعریف شده، نه در این runner.
- **پایداری زمان اجرا.** یک اجرا یک مشاهده است، نه SLA.

### محدودیت عملیاتی که باید بدانید

endpoint رایگان سقف **۵۰ درخواست در روز** دارد و هر نمونه می‌تواند تا دو تلاش مصرف کند. اگر هر ۴۰ نمونه در تلاش اول موفق شوند، ۴۰ درخواست جا می‌شود؛ اما برای همهٔ تلاش‌های دوم فقط ۱۰ درخواست باقی می‌ماند و حالت بدبینانه به ۸۰ درخواست می‌رسد. بنابراین اجرای کامل ممکن است در بعضی اجراها جا شود، ولی این سهمیه آن را تضمین نمی‌کند. برای اجرای نمایشی `--limit 8` یا `--limit 10` را به‌کار ببرید و نتیجه را «نمونهٔ محدود» بنامید، نه معیار کامل.

سنجهٔ دومی هم هست که در README پنهان نمی‌ماند: **پاسخ‌های زنده کند یا ناموفق‌اند.** در دوازده پرسش زندهٔ اندازه‌گیری‌شده در ۲۰۲۶-۱۰-۱۲، هشت پاسخ در ۱۲ تا ۴۶ ثانیه رسیدند، دو پاسخ ۵۰۴ شدند (بودجهٔ ۶۰ ثانیه‌ای تمام شد) و یکی ۵۰۲ (خطای provider). دو پرسش هم به‌درستی از پاسخ دادن دست کشیدند. این رفتار endpoint رایگان است، نه نقص سامانه — و سامانه در همهٔ این حالت‌ها پیام ثابت و بدون اثر انگشت می‌دهد.

## بررسی کیفیت

```bash
# API
(
  cd apps/api
  uv run --locked ruff check .
  uv run --locked ruff format --check .
  uv run --locked mypy app
  uv run --locked pytest -q
)
```

```bash
# رابط
(
  cd apps/web
  npm run lint
  npm run typecheck
  npm run format:check
  npm run build
  npm run test:proxy
  npm run test:answers
  npm run test:sources
  npm run test:render
  npm run test:source-render
  npm run test:transitions
  npm run test:navigation
)
```

سه آزمون `test:proxy`، `test:answers` و `test:sources` به یک backend زنده نیاز دارند؛ بدون آن‌ها با ۵۰۲ شکست می‌خورند نه با ۴۰۱، چون proxy پاسخ بالادست را برمی‌گرداند.

جزئیات هر بررسی، شامل آنچه در اجرا شکست خورد و چه چیزی اصلاح شد، در [راهبرد آزمون](docs/TESTING.md) آمده است.

## آنچه این پروژه نیست

- **OCR، اتصال Drive، چند شرکت، حافظهٔ گفتگو، کش معنایی و توزیع‌شده** خارج از نسخهٔ اول‌اند.
- **رنک‌بندی معنایی با LLM** اختیاری و پیش‌فرض خاموش است (`RERANK_ENABLED=false`). روشن کردنش نخستین نقطه‌ای است که متن سند از فرایند بیرون می‌رود؛ فقط corpus ساختگی و غیرشخصی مجاز است.
- **کیفیت پاسخ خودکار سنجیده نمی‌شود.** آنچه خودکار سنجیده می‌شود این است که پاسخ آمد، استناد درست بود و سند ممنوع نشت نکرد. درستی معنایی کار بازبینی انسانی است.
- **عمومی برای production نیست.** نشست محلی، بدون چند نمونه‌ای، بدون audit trail و بدون سیاست نگهداری داده.

## سرویس‌های محلی

- **embedding:** Ollama محلی در `127.0.0.1:11434`، مدل `nomic-embed-text-v2-moe:latest`، ۷۶۸ بُعد، با پیشوندهای query/document و `truncate=false`. digest بررسی‌شده: `ff9c2f10ef5e`.
