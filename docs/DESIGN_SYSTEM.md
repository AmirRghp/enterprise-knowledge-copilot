# نظام طراحی

## جهت و مرجع

رابط فارسی و راست‌به‌چپ فضای دانش سازمانی، زبان بصری تیره و داده‌محور [WattVision](references/wattvision-DESIGN.md) را برای محصول خود اقتباس می‌کند: زمینهٔ آرام، سطوح مشخص، تأکید فیروزه‌ای و وضعیت‌های خوانا. فایل مرجع دربارهٔ پایش برق است؛ نمودار مصرف، واحد پول `Bs.` و اصطلاحات آن جزو این محصول نیستند. [مرجع Notion](references/notion-DESIGN.md) فقط سابقهٔ طرح پیشین است و مبنای UI جاری نیست.

هدف هر صفحه روشن‌کردن اقدام اصلی و وضعیت داده است. رنگ به‌تنهایی حامل مجوز، خطا، وضعیت پردازش یا استناد نیست. UI هیچ عنوان، شمار یا محتوای سند مدیریتی را به کارمند آشکار نمی‌کند؛ مرجع مجوز همچنان API است.

## رنگ و توکن

| نقش | مقدار | کاربرد |
|---|---|---|
| زمینهٔ اصلی | `#121212` | بوم تمام صفحات؛ `color-scheme: dark` |
| سطح کارت و فرم | `#1E1E1E` | پنل، کارت، dialog و نوار کناری |
| سطح hover | `#252525` | ردیف و کنترل تعاملی |
| مرز ظریف | `#2C2C2E` | جداکننده و کارت؛ برای ورودی از مرز نمایان‌تر استفاده شود |
| اقدام و دادهٔ اصلی | `#00E5FF` | دکمهٔ اصلی، پیوند و دادهٔ برجسته |
| موفقیت و وضعیت عادی | `#32D74B` | وضعیت همراه برچسب متنی |
| خطا و خطر | `#FF453A` | پیام خطا، اقدام مخرب و هشدار جدی |
| متن اصلی | `#FFFFFF` | عنوان و متن اصلی |
| متن ثانویه | `#98989D` | راهنما و فرادادهٔ خوانا |
| زمینهٔ هشدار | `#3A1C1C` | هشدار با متن قرمز و خط آغازین ۴px |

متن روی فیروزه‌ای تیره (`#121212`) است؛ سفید روی آن کنتراست کافی ندارد. وضعیت warning غیرمخرب نیز از متن و نشانهٔ روشن استفاده می‌کند و با خطای قرمز یکسان نمایش داده نمی‌شود. برای hover، disabled و focus مقدارهای مشتق‌شده باید در مرورگر با سنجش کنتراست بررسی شوند؛ نام توکن به‌تنهایی مدرک دسترس‌پذیری نیست.

توکن‌های `apps/web/src/app/tokens.css` سه لایه دارند: رنگ و اندازهٔ پایه، نام‌های معنایی و مقادیر ویژهٔ جزء. CSS صفحه‌ها از نام‌های معنایی یا جزء استفاده می‌کند؛ نام‌های رنگی طرح قدیمی از رابط حذف می‌شوند. تم روشن و کلید تغییر تم در این مرحله وجود ندارند.

## قلم و اندازه

Vazirmatn variable نسخهٔ `33.003`، با مجوز OFL و بارگذاری محلی `next/font/local`، قلم فارسی تأییدشده می‌ماند. برای اعداد و شناسه‌های فنیِ واقعاً جدولی از `ui-monospace` سیستمی استفاده می‌شود؛ قلم یا درخواست شبکه‌ای تازه اضافه نمی‌شود. پیشنهاد Inter و JetBrains Mono/Fira Code در مرجع، برای محتوای لاتین/عددی آن است و جای قلم فارسی را نمی‌گیرد. متن مختلط، نیم‌فاصله، اعداد و URLها باید با جهت محلی مناسب دیده شوند.

عنوان صفحه ۲۴px با وزن ۶۰۰، عنوان بخش ۱۸ تا ۲۰px و متن رابط ۱۴ تا ۱۶px است. متن طولانی پاسخ و سند حداقل ۱۶px و ارتفاع خط باز دارد. عدد برجستهٔ موجود، اگر صفحه واقعاً آن را دارد، می‌تواند ۳۲px و monospace باشد؛ KPI ساختگی اضافه نمی‌شود.

## شبکه و فاصله

مقیاس غالب فاصله مضرب ۸px است: ۸، ۱۶، ۲۴ و ۳۲px. فاصلهٔ داخلی کارت ۲۰px مطابق مرجع است؛ فاصله‌های کوچک‌تر فقط برای هم‌ترازی ریزمتن و آیکون مجازند. کارت پایه زمینهٔ `#1E1E1E`، شعاع ۱۶px و مرز `1px solid #2C2C2E` دارد. سایهٔ سنگین، گرادیان تزئینی و کارت‌های رنگی پاستلی به کار نمی‌روند.

در دسکتاپ پوسته و صفحه‌هایی که واقعاً دو ناحیه دارند روی شبکهٔ ۱۲ستونی می‌نشینند: محتوای اصلی حدود ۸ ستون و پنل کناری حدود ۴ ستون. نمای کلی اقدام اصلی و راه‌های مجاز بعدی را نشان می‌دهد؛ چت، تاریخچه را کنار متن گفت‌وگو می‌گذارد؛ منابع و صفحه‌های مدیر فهرست، جزئیات و فرم را برحسب محتوا مرتب می‌کنند. هیچ صفحه‌ای فقط برای پرکردن شبکه نمودار یا کارت آماری نمی‌گیرد.

زیر ۱۰۲۴px ناوبری فشردهٔ نقش‌محور باید تمام مقصدهای مجاز را نگه دارد. در ۳۲۰ تا ۷۶۷px صفحه تک‌ستونه است، فهرست‌ها می‌شکنند و متن سند/پاسخ بدون اسکرول افقی خوانده می‌شود. اندازهٔ هدف لمس کنترل‌های اصلی حداقل ۴۴px است. در عرض‌های ۷۶۸ و ۱۰۲۴px چیدمان تنها وقتی چندستونه می‌ماند که خوانایی حفظ شود.

## اجزا و حالت‌ها

- **دکمه:** اصلی فیروزه‌ای با متن تیره؛ ثانویه سطح تیره با مرز روشن؛ خطر قرمز با فعل روشن و تأیید متناسب. حالت hover، focus، disabled و loading باید از هم متمایز باشند. دکمهٔ غیرفعال نباید فقط با opacity کم‌رنگ شود.
- **ورودی و فرم:** زمینهٔ سطح، متن سفید، برچسب دائمی، مرز قابل تشخیص و focus آشکار. ایمیل، رمز، شناسه و مقدار فنی می‌توانند LTR باشند. خطا با پیام فارسی متصل به ورودی اعلام شود.
- **کارت، جدول و فهرست:** کارت ۱۶px/۲۰px؛ ردیف‌ها با خط `#2C2C2E` جدا و hover به `#252525` تبدیل شوند. عنوان، نقش، وضعیت و اقدام جدا و قابل پیمایش بمانند.
- **هشدار و وضعیت:** خطای مهم روی `#3A1C1C` با متن `#FF453A` و خط آغازین ۴px؛ موفقیت با سبز و برچسب. `pending`، `indexing`، `ready`، امتناع، خطای سرویس و نبود مجوز پیام‌های متفاوت دارند.
- **چت و استناد:** پاسخ، نوبت کاربر، انتظار، retry/cancel و جزئیات منابع از نظر سطح و سلسله‌مراتب متمایز باشند. نقل‌قول و پیوند منبع فقط در محل مجاز فعلی و با متن معتبر نمایش داده شوند؛ تغییر ظاهر نباید قرارداد استناد را عوض کند.
- **Prompt Composer:** ورودی گفت‌وگو سطح تیرهٔ کدر، حاشیهٔ گرادیانی متحرک و ۱px، آواتار Warp و دکمهٔ ارسال با حالت انتظار دارد. هاله‌های رنگی پشت سطح قرار می‌گیرند و در حالت عادی فقط از حاشیه دیده می‌شوند؛ سطح frosted فقط هنگام انتظار مجاز است. focus مرز خنثی و قابل‌تشخیص دارد و به فیروزه‌ای یا آبی تبدیل نمی‌شود. این رنگ‌های صورتی/آبی/بنفش/فیروزه‌ای استثنای تزئینی همین جزء هستند و جای توکن‌های وضعیت یا اقدام محصول را نمی‌گیرند. ورودی فارسی RTL و خودگستر تا ۲۸۰px است؛ واژه‌های فارسی برای حفظ اتصال حروف به‌صورت یکپارچه متحرک می‌شوند و سقف پیام همان ۲۰۰۰ نویسه می‌ماند. Enter خط جدید می‌سازد و Ctrl/⌘+Enter ارسال می‌کند؛ IME نباید با میان‌بر قطع شود. شمارنده و برچسب دسترس‌پذیر، focus آشکار، کنترل غیرفعال/در حال ارسال و `prefers-reduced-motion` الزامی‌اند؛ در حالت کاهش حرکت، انیمیشن‌ها متوقف یا ایستا می‌شوند و Warp بیرون viewport سرعت صفر می‌گیرد. قابلیت پیوست تا پشتیبانی API نمایش داده نمی‌شود.
- **Dialog:** سطح تیره، مرز خوانا، عنوان و اقدامهای واضح؛ فوکوس آغازین/بازگشتی، Escape، خطای درون modal و تأیید اقدامات حساس حفظ شوند. فرم فقط پس از ذخیرهٔ موفق بسته شود.
- **خالی و قطع سرویس:** دلیل و اقدام بعدی با متن فارسی ارائه شود؛ جزئیات حساس، secret، stack trace یا وجود سند غیرمجاز فاش نشود.

## دسترس‌پذیری و قرارداد موجود

ساختار عنوان‌ها، `lang="fa"` و `dir="rtl"`، skip link، مسیر صفحه‌کلید، `aria-current`، اعلام وضعیت و کاهش حرکت حفظ شوند. focus باید مستقل از رنگ زمینه دیده شود؛ متن معمولی دست‌کم نسبت کنتراست ۴٫۵:۱ و کنترل‌های مهم مرز قابل تشخیص داشته باشند. نمادها از Lucide موجود استفاده می‌کنند و آیکون تزئینی از فناوری کمکی پنهان می‌ماند.

ورود، setup فقط برای نصب بدون کاربر، نمایش نام سازمان، نقش مدیر/کارمند، مدیریت اسناد و کاربران، زنجیرهٔ provider، system prompt، سهمیه و گفت‌وگوی ماندگار همان رفتار و محدودیت‌های [PRD](PRD.md)، [معماری](ARCHITECTURE.md) و [امنیت](SECURITY.md) را دارند. نظام طراحی مجوز تغییر API، schema، داده یا محتوای مدل نیست.
