# راهنمای امنیت

## 1. احراز هویت

**وضعیت:** Part 4 مسیرهای `POST /api/auth/login`، `POST /api/auth/logout` و `GET /api/auth/me` را در `apps/api/app/api/auth.py` با منطق `app/auth/` و محدودسازی login پیاده و محلی اعتبارسنجی کرده است. Part 4 هنوز منتشر نشده و در انتظار بازبینی کاربر است. رابط کاربری، صفحهٔ ورود و پراکسی هم‌مبدأ وجود ندارند. موارد زیر با برچسب «پیاده‌شده» رفتار فعلی‌اند؛ پیشنهادهای آینده صریحاً مشخص شده‌اند.

روش: هش گذرواژه با Argon2id؛ گذرواژه‌های seed حداقل ۱۲ نویسه دارند؛ نشست opaque تصادفی و فقط hash آن در DB. کوکی `HttpOnly; SameSite=Lax`، در HTTPS برابر `Secure`، عمر 8 ساعت؛ logout نشست را باطل و کوکی را حذف می‌کند. ورود موفق نشست ارسالی را همراه با صدور نشست تازه اتمی باطل می‌کند؛ نشست‌های دستگاه‌های دیگر دست‌نخورده می‌مانند. نقش و فعال‌بودن حساب در هر درخواست از DB خوانده می‌شوند؛ حساب‌ها فقط با CLI و گذرواژه‌های env seed می‌شوند.

## 2. مجوزدهی

- مجوز هر سند پیش از بازیابی و در تمام مراحل retrieval، rerank، تولید، استناد و نمایش بررسی شود.
- کارمند فقط اسناد عمومیِ فعال، جاری و آماده را ببیند؛ مدیر به آن‌ها و اسناد مدیریتی دسترسی دارد.
- عملیات بارگذاری، تغییر دسترسی و حذف فقط برای مدیر است و کنترل آن در backend انجام می‌شود.
- نقش ارسالی در متن، پارامتر یا header کاربر قابل اعتماد نیست. در پرسش ترکیبی، بخش عمومی را پاسخ دهید و دربارهٔ وجود یا جزئیات بخش غیرمجاز چیزی فاش نکنید.
- پیش از تحویل پاسخ و خواندن متن منبع، مجوز و نسخهٔ جاری دوباره بررسی شود.
- گسترش دسترسی در جایگزینی فقط پس از فعال‌سازی revision تازه اعمال شود؛ نسخهٔ قدیمی نباید برای کاربران تازه‌مجازشده باز شود. کاهش دسترسی فوراً اعمال شود.

## 3. اسرار

- کلیدها، گذرواژه‌ها و کوکی‌های واقعی را در کد، مستندات، log، خروجی ابزار یا Git قرار ندهید.
- `OPENROUTER_API_KEY` فقط از محیط خصوصی اجرا خوانده شود؛ فایل محیطی محلی commit نشود. مقدار یا وضعیت کلید محلی را در مستندات ننویسید.
- embedding محلی از Ollama با مدل `nomic-embed-text-v2-moe:latest` و بُعد ۷۶۸ استفاده می‌کند؛ endpoint محلی پیش‌فرض `http://localhost:11434` است.
- OpenRouter rerank اختیاری و به‌طور پیش‌فرض خاموش است (`RERANK_ENABLED=false`). در صورت فعال‌سازی از همان `OPENROUTER_API_KEY` تولید استفاده می‌کند و کلید جدا ندارد. endpoint رایگان NVIDIA دادهٔ درخواست را برای امنیت و بهبود محصول ثبت می‌کند؛ فقط corpus ساختگیِ غیرشخصی و غیرمحرمانهٔ prototype ارسال شود. هیچ دادهٔ واقعی تا بازبینی حریم خصوصی و شرایط ارائه‌دهنده ارسال نشود.

## 4. متغیرهای محیطی

**عمومی/غیرمحرمانه:** `OPENROUTER_BASE_URL`، `OPENROUTER_MODEL`، `EMBEDDING_PROVIDER`، `OLLAMA_BASE_URL`، `OLLAMA_EMBED_MODEL`، `EMBEDDING_DIMENSION`، `EMBEDDING_MAX_TOKENS`، `EMBEDDING_TRUNCATE`، `RERANK_ENABLED`، `RERANK_PROVIDER`، `OPENROUTER_RERANK_MODEL`، `WEB_ORIGIN`، `API_BASE_URL` و `SESSION_TTL_SECONDS`. این تنظیم‌ها در server env هستند؛ به client expose نشوند مگر نیاز مشخصی وجود داشته باشد.

**خصوصی:** `OPENROUTER_API_KEY`، `DB_PASSWORD`، `SEED_EMPLOYEE_PASSWORD` و `SEED_MANAGER_PASSWORD`. rerank و generation کلید مشترک OpenRouter دارند. تنظیم اتصال DB (`DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER`) نیز فقط در محیط backend نگهداری شود. `.env.example` در ریشه برای نام متغیرها و راه‌اندازی است؛ مقدارها یا وضعیت فعلی credentialهای محلی را از روی آن حدس نزنید. `.env` محلی باید خارج از Git بماند. فایل محیطی را از ریشهٔ repository صریحاً بارگذاری کنید؛ مقدارها را هنگام ساخت connection string یا خطا log نکنید.

## 5. امنیت API

- ورودی پرسش، فایل و فراداده سمت سرور اعتبارسنجی شود؛ پسوند فایل به‌تنهایی اثبات نوع محتوا نیست.
- درخواست‌های تغییردهنده، از جمله login، ابتدا باید Origin منطبق داشته باشند؛ Origin غایب یا نامنطبق پیش از محدودکننده رد می‌شود. پس از آن یک limiter مشترک در هر نمونهٔ app با پنجرهٔ لغزان ۶۰ثانیه‌ای، حداکثر ۵ تلاش برای هر جفت IP/شناسه و ۳۰ تلاش برای هر IP اعمال می‌کند. حدود با `LOGIN_RATE_PAIR_LIMIT=5`، `LOGIN_RATE_IP_LIMIT=30` و `LOGIN_RATE_WINDOW_SECONDS=60` تنظیم می‌شوند. ورود ناموفق در هر دو سهم شمارش می‌شود؛ تلاش ردشده به علت سقف جفت نیز تا پرشدن سهم IP از بودجهٔ IP مصرف می‌کند. کلیدهای نگهداری‌شده به `LOGIN_RATE_MAX_KEYS=10000` محدودند؛ در ظرفیت کامل درخواست fail-closed و با 429 و `Retry-After` رد می‌شود. محدودیت ۱۰ درخواست پاسخ در دقیقه برای هر کاربر هنوز به پارت ۱۵ موکول است.
- کلید IP از آدرس peer واقعی اتصال گرفته می‌شود؛ هدرهای `Forwarded` و `X-Forwarded-*` مبنای اعتماد نیستند و Uvicorn باید با `proxy_headers=False` اجرا شود. برای اجرای مستقیم Uvicorn بیرون از `python -m app` نیز `--no-proxy-headers` را صریحاً بدهید. محدودیت شناخته‌شده: در اجرای فعلی API محلی، همهٔ peerها loopback هستند و پشت پراکسی محلی در سهم IP مشترک جمع می‌شوند؛ محدودسازی IPهای کلاینت به forwarding صریح و محدود به پراکسی‌های مورد اعتماد نیاز دارد و هنوز پیاده نشده است.
- مقادیر محدودسازی از environment هنگام ساخت app خوانده می‌شوند؛ پس از تغییر تنظیم‌ها، فرایند API را restart کنید.
- Argon2 در مسیر async مستقیم اجرا نمی‌شود؛ کار هش به ظرفیت thread محدود (۴ کار هم‌زمان) سپرده می‌شود تا تعداد کارهای محاسباتی محدود بماند.
- CORS فقط به مبدأهای لازم محدود شود؛ در معماری پیشنهادی، مرورگر از پراکسی same-origin استفاده می‌کند.
- شناسهٔ نقش، سطح دسترسی سند و مجوز API هرگز از ادعای کاربر پذیرفته نشوند.
- خطاهای API نباید query، سند غیرمجاز، stack trace یا secret افشا کنند. منبع غیرموجود و غیرمجاز یک پاسخ عمومی 404 دارند؛ فهرست و شمار فقط از اسناد مجاز ساخته شود. رندر Markdown باید HTML خام را غیرفعال یا sanitize کند و URLهای javascript/اجرایی را نپذیرد.

## 6. حفاظت از داده

- corpus این مخزن ساختگی است؛ دادهٔ واقعی کارکنان، رمز یا کلید وارد نکنید.
- اتصال پروژه به نمونهٔ موجود PostgreSQL 16 با نام `rag-postgres` از host port `5433` و پایگاه جداگانهٔ `enterprise_knowledge_copilot` انجام می‌شود. در ۲۰۲۶-۱۰-۰۴ پایگاه‌های `enterprise_knowledge_copilot` و `enterprise_knowledge_copilot_test` با حساب محدود `enterprise_knowledge_copilot` ساخته شد و schema با migration `0001` اجرا شد. این حساب superuser، `CREATEDB` یا `CREATEROLE` ندارد و فقط مالک همین دو پایگاه است.
- از حذف، بازسازی، تغییر پیکربندی یا پاک‌سازی container/volume و داده‌های قدیمی `rag-postgres` خودداری کنید. هر عملیات فقط باید پایگاه اختصاصی پروژه را هدف بگیرد.
- ساخت پایگاه‌ها و حساب محدود یک اقدام superuser و جدا از runtime برنامه است: اسکریپت idempotent `apps/api/sql/provision.sql` فقط objectهای جدید محدود به این پروژه می‌سازد و رمز از بیرون از مخزن و از راه متغیر محیطی `EKC_DB_PASSWORD` داخل container به `psql` می‌رسد؛ این روش عمداً به‌جای `-v` یا `-e` انتخاب شد چون هر دو مقدار را در argv فرایند آشکار می‌کنند. بررسی مالکیت و مجوز پیش از هر تغییری اجرا می‌شود و برخورد با کد خروج غیرصفر و بدون تغییر متوقف می‌شود. افزونهٔ `vector` عمداً بخشی از migration نیست و همین اسکریپت آن را می‌سازد، چون حساب کاربرد مجوز ساخت افزونه را ندارد.
- محدودیت شناخته‌شده: مجوز CONNECT در سطح connection قابل بستن نیست، چون سرویس `rag-postgres` موجود به‌صورت پیش‌فرض به `PUBLIC` دسترسی می‌دهد و لغو آن به‌معنای تغییر پایگاه‌های قدیمی و ممنوع است. مرز مجوز در لایهٔ application و با allowlist نام پایگاه‌داده در `apps/api/app/db/url.py` اعمال می‌شود؛ سخت‌سازی مجوزهای `rag_support` تصمیمی جداگانه و خارج از محدودهٔ این پروژه است.
- پیش از استفادهٔ واقعی، سیاست retention، backup و پاک‌سازی فیزیکی مشخص شود. log عادی متن خام پرسش، پاسخ، prompt یا سند را ذخیره نکند.

رمزها با Argon2id و نشست‌ها به‌صورت hash ذخیره می‌شوند. اجرای محلی HTTP فقط روی loopback؛ انتشار عمومی نیازمند HTTPS است. پاک‌سازی فیزیکی/backup و مدت retention قبل از ورود دادهٔ واقعی تعیین شوند؛ حذف منطقی بلافاصله بازیابی و نمایش منبع را قطع کند. فقط زمینهٔ مجاز به OpenRouter ارسال می‌شود؛ دادهٔ ارسال‌شده را recheck بعدی نمی‌تواند پس بگیرد. endpoint رایگان rerank داده‌ها را برای امنیت و بهبود محصول ثبت می‌کند؛ ارسال اطلاعات شخصی یا محرمانه ممنوع است. استفاده از دادهٔ واقعی در آینده نیازمند بازبینی حریم خصوصی/شرایط ارائه‌دهنده است.

## 7. ثبت رویدادها

- گذرواژه، API key، token نشست و محتوای حساس را ثبت نکنید.
- در صورت پیاده‌سازی، شناسهٔ اجرا، زمان، وضعیت، نسخهٔ مدل و شناسه/رتبهٔ منابع مجاز برای عیب‌یابی کافی است.
- خطاهای provider را پیش از ثبت از headerها، tokenها و payload حساس پاک کنید.

## 8. بارگذاری فایل

- نسخهٔ اول فقط `.md` و `.txt` را می‌پذیرد؛ سقف 1 MiB هر فایل، UTF-8، 100 سند فعال و 2000 قطعهٔ جاری؛ اندازه و encoding پیش از provider بررسی شوند. متن staging در DB ذخیره شود و فایل خام جدا نگهداری نشود.
- بارگذاری و تعیین سطح دسترسی فقط برای مدیر است. سند با سطح دسترسی نامعلوم هرگز عمومی فرض نشود.
- متن فایل دادهٔ نامطمئن است، نه دستور؛ فایل نباید نقش یا سیاست دسترسی را تغییر دهد.
- فقط سند فعال، جاری و آماده وارد جست‌وجو شود؛ جایگزینی یا کاهش دسترسی باید دسترسی به نسخهٔ قبلی را مطابق قواعد طراحی کنترل کند.
